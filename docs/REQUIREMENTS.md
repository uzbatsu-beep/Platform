# Функциональные и нефункциональные требования NEON (REQUIREMENTS)

## 1. Утверждённые функциональные требования

### 1.1 Platform Core (Phase 1A — Foundation)
- **FR-CORE-01 (Identity & AuthProvider):** абстракция `AuthProvider`; в MVP — локальная аутентификация (Argon2id), защищённые серверные сессии, безопасный bootstrap первого администратора и CLI-процедура восстановления административного доступа.
- **FR-CORE-02 (RBAC со скоупами):** права `<module>:<resource>:<action>` с ограничением по области (`Global`, `Site`, `Department`, `Own`), проверяемые строго на сервере.
- **FR-CORE-03 (Оргструктура):** единый справочник `Organization` → `Site` → `Department` → `Location`.
- **FR-CORE-04 (Реестр модулей):** `ModuleManifest`, проверка совместимости версий и зависимостей при старте, управление активностью модулей.
- **FR-CORE-05 (События и контракты):** минимальная инфраструктура **Transactional Outbox** (`core_outbox_events`, `core_processed_events`, retry/DLQ), а также `QueryPort` и `CommandPort` для межмодульного взаимодействия.
- **FR-CORE-06 (Аудит):** журналирование критичных изменений с настраиваемыми сроками хранения (ретенцией); интеграция с SIEM — в следующей фазе.
- **FR-CORE-07 (Безопасные документы и вложения):** приём `PDF`, `PNG`, `JPG/JPEG` и инженерных форматов (`DXF`, `DWG`, `STEP`/`STP`, `CSV`, `TXT`, `DOCX`, `XLSX`) с безопасным скачиванием, проверкой magic bytes и настраиваемыми лимитами размеров (без серверного парсинга и CAD-просмотрщика DXF/DWG).
- **FR-CORE-08 (Поиск, настройки, i18n, уведомления):** унифицированный поиск (PostgreSQL `tsvector` / SQLite `FTS5`) с RBAC-фильтрацией; полноценный i18n-слой с русским языком в MVP (без захардкоженных строк, EN — в следующей фазе).
- **FR-CORE-09 (Согласованный бэкап и диагностика):** консистентное резервное копирование БД + файловых вложений с манифестом и проверкой восстановления; `/health/live`, `/health/ready`, метрики.
- **FR-CORE-10 (Готовность к обмену данными):** стабильные `UUIDv7`, `source_instance_id` и `schema_version` у всех сущностей для будущего версионированного экспорта/импорта (без копирования сырого файла SQLite в PostgreSQL).

### 1.2 Первый прикладной модуль MVP (Phase 1B — Vertical Slice)
- **`mod-equipment` (Реестр и паспорт оборудования):** иерархия `Equipment` / `EquipmentComponent`, виртуализированная таблица, карточка паспорта + правый Inspector, безопасные вложения, история изменений, 2–3 виджета Dashboard.

### 1.3 Последующие прикладные модули (Phase 2–4)
`mod-hr-org`, `mod-shifts`, `mod-tasks`, `mod-cmms`, `mod-inventory`, `mod-knowledge`, `mod-training`, `mod-calculators`, `mod-analytics`, `mod-integrations` (изолированный OT/IT контур), `mod-ai`.

## 2. Нефункциональные требования
- **NFR-01 (Air-gapped):** 0 обращений к внешним CDN/интернету в production (локальные шрифты, иконки, JS/CSS, строгий CSP `default-src 'self'`, офлайн-установка и обновление).
- **NFR-02 (Два режима на общей кодовой базе):** Standalone (без интернета, без внешней СУБД, без Node.js) и Server (Linux/Windows, TLS, PostgreSQL 18+).
- **NFR-03 (Производительность):** воспроизводимые нагрузочные испытания на 50 000 записей и проверка лимитов загрузки файлов; публикация реальных замеров без недоказанных заявлений.
- **NFR-04 (Надёжность и безопасность):** secure-by-default, graceful shutdown, идемпотентность фоновых задач и событий, CI-проверка зависимостей и границ модулей.
